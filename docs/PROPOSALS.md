## 一、命名提案

现名 dukangalex/sing-box-1 只是 fork 占位名，且与 dukangalex/sing-box（SagerNet 官方内核 fork）只差后缀、极易混淆，必须改名脱钩。候选（按推荐序）：

### 方案 1（推荐）：angela-singbox-suite ／ 中文别名「全家盒」
- 理由：「全家桶」是上游的招牌叫法，别名换成自家的「全家盒」——盒对应 box、一盒装全套协议，意思不变、说法是自己的；与星轨（AngelaMihomo 客户端）正好一对：星轨管客户端导入使用，全家盒管服务端一键部署。
- 仓库名 angela-singbox-suite 与自有仓命名惯例一致（angela-link、angela-cinematic、angela-uxui）。

### 方案 2：angela-deploy-box ／ 中文别名「铺路盒」
- 理由：突出「部署」本职——把节点铺到服务器上；deploy-box 直白易懂。别名「铺路盒」取铺路搭桥之意，稍弱于方案 1 的对仗。

### 方案 3：angela-sb-toolkit ／ 中文别名「百节箱」
- 理由：toolkit 定位工具箱（脚本＋Docker＋订阅模板）；「百节箱」取多节多协议之意。缺点：sb 缩写辨识度低，新用户不易懂。

注：三个方案的仓库名都避开了与 dukangalex/sing-box 内核仓的混淆。拍板后执行顺序：先等用户电脑窗口用本人登录态在 GitHub 设置页改名（与问猫 angela-onu 改名同窗口一并办），再做仓内标识替换（README 标题、脚本内自引用 raw 链接改指自有仓、sb 快捷方式文案等），最后登记为自有化项目第 15 项并同步自有化项目空间 / Angela Lab / 工具清单 / TOOL_INDEX。

## 二、上游同步口径提案（建议，未建任何定时任务）

背景：上游约周更（v1.3.x 近乎每周一版），但变更以新协议适配、客户端订阅格式跟进、bug 修复为主；本仓是部署脚本，一旦跟版失误影响的是服务器上的真实节点，稳定性优先于新鲜度。

建议口径：

1. **纳入「自有化项目定时维护」月度错峰排班**，给本项目分配一个未占用日期（现有排班：5 百工坊、7 图志、8 安渡、12 镜语、15 通译、18 毫厘、20 边关、22 幕墙映画、25 绳墨、10 星轨；建议本项目排 **每月 27 日**，北京时间上午，与其他项目错开）。只提案、不在本轮建 cron，等主聊天 / 用户定夺后由主聊天统一建。
2. **月度维护动作**：对比上游当月 Release 与提交，逐条过三类才收编——① 安全修复（如私钥处理、校验类）优先收；② 与自家在用协议 / 客户端相关的 bug 修复按需收；③ 新协议、新客户端格式等功能新增，进候选台账，不自动收，等真实需求出现再收。
3. **收编门槛沿用总章程**：候选先入台账；收编须自有化落地（剥离物不回潮——重点盯上游新增的统计 / 推广 / 外发）、过自家基线复测（bash -n + shellcheck + 一次性容器冒烟）才算数。
4. **force_version 联动**：上游用 force_version 钉内核版本；自有化后内核版本跟随星轨（AngelaMihomo）的内核升级节奏，不单独追 sing-box 内核预发布版。
5. **例外通道**：上游出现安全级修复（如凭据处理漏洞）时不等月度排班，发现即报主聊天、由主聊天决定是否提前收编。
